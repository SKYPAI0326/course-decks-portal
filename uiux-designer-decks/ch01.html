    故事

    你接到的案子：一間找不到工作的工作室

    整門課都在處理同一個案子。我們先聽聽這間工作室的主管怎麼說：

    「我每天早上把當天的工作貼在群組，大家往上滑找自己要做什麼。訊息一多就被洗掉，最後還是跑來問我。」
    「工作室每個人都要看。有人整天坐在電腦前，也有人剛到客戶現場，手上只有手機。我最在意的是：用手機能很快找到待處理的工作。」
    「怎樣算解決？成員能在手機上自己找到待處理的工作，看完內容就把它完成，不用再回群組問我『現在要做哪一件』。」

    講什麼：主管的三段話：現況、誰在用、怎樣算解決。

    對應講義：故事／你接到的案子。

    接下一張：這三段話裡沒有提到任何按鈕、顏色或畫面。

    主管講的是一個問題，不是畫面

    • 整門課每一份講義，都是在把這個 App 往前做一步。

    這門課在學什麼

    UI 和 UX 是什麼

    打開一個 App，你看到的每個按鈕、每行字、每種顏色，以及按下去之後會發生什麼事，都是有人事先設計好的。

    名詞白話意思出問題時長什麼樣
    UI
    User Interface，使用者介面    		畫面長什麼樣：按鈕放哪、字多大、用什麼顏色。結帳按鈕顏色太淡，看不出它可以按。
    UX
    User Experience，使用者體驗    		用起來順不順：使用者能不能很快找到要按的地方、不會按錯、知道下一步。要點五層選單才找得到結帳；按錯了也沒有提示怎麼回去。

    講什麼：用白話對照 UI（長什麼樣）和 UX（順不順），各配一個出問題的例子。

    對應講義：這門課在學什麼／UI 和 UX 是什麼，表格。

    再往深一層

    UX 一定要先說清楚「誰、在哪、要完成什麼」

    要先問清楚放到工作室的故事裡
    誰在用工作室成員，不是主管，也不是設計師自己。
    在什麼情況下用可能在客戶現場，只有手機，只想很快看一眼。
    要完成什麼找到今天待處理的工作，看懂內容，做完標記完成。
    怎樣算成功做得到：真的找到正確那一件，沒有標錯。
    做得快：不用滑半天，也不用回群組問人。
    做得安心：按下去知道有沒有成功，用完不覺得挫折。

    三把尺出自國際標準 ISO 9241-11 對「好用」的定義，原文是有效、有效率、滿意，這裡換成白話。

    講什麼：同一個 App，換一個人、換一個情況，順不順的答案就不一樣；成功用做得到、做得快、做得安心三把尺判斷。

    對應講義：再往深一層一節的四問表與三把尺說明。之後每張畫面都會回來用這三把尺檢查。

    接下一張：有了這四個答案，UI 和 UX 的分工就清楚了。

    這門課在學什麼

    UI 和 UX 的分工

    UX 決定

    「要讓這個人完成什麼、經過哪幾步」

    先登入，再看清單，點一筆看詳情，最後標記完成；標記前要再確認一次，免得按錯。

    UI 決定

    「每一步的畫面上放什麼、怎麼讓人一眼看懂」

    清單上哪一行字最大、期限用什麼顏色、「標記完成」按鈕要多醒目。

    兩者常常一起出問題，所以這門課把它們放在一起學。

    講什麼：UX 管流程步驟，UI 管每一步的畫面；兩者會一起出問題，例如按鈕淡到看不出能按，成員還是會回群組問人。

    對應講義：UI 和 UX 的分工。

    接下一張：設計師在工作上實際做的是什麼。

    這門課在學什麼

    設計師在工作上做什麼

    在工程師寫程式之前，先把 App 的每一個畫面畫出來，確認「看得清楚、用得順」之後，工程師才照著做。

    1. 聽懂主管和成員的問題
    2. 決定成員要經過哪幾個畫面
    3. 把每個畫面畫出來
    4. 串成可以點的樣品給成員試
    5. 修好之後交給工程師
    就像蓋房子前先畫設計圖：設計圖上改一條線幾乎不用成本，房子蓋好才發現廁所門開錯邊，就得敲掉重來。

    講什麼：設計師的工作流程，以及為什麼在設計階段改比程式寫完再改便宜很多。

    對應講義：設計師在工作上做什麼，含蓋房子的比喻。

    用什麼工具

    Figma 是什麼

    • 專門用來畫 App 和網站畫面的軟體。打開瀏覽器、登入帳號就能用，不用安裝。
    • 可以把它想成「專門畫畫面的簡報軟體」：一樣可以拉框、打字、上色，但多了設計師需要的功能：
      • 把顏色存成有名字的色票，改一次、整份檔案一起變
      • 把同一個按鈕做成可以重複使用的零件
      • 把畫面串起來，做成可以點來點去的「原型」
    • 檔案存在雲端、會自動儲存，把連結傳給別人，對方就能打開來看。

    講什麼：Figma 的定位與三個設計師專用功能；第一個功能就是第一章要學的顏色變數。

    對應講義：用什麼工具／Figma 是什麼。

    第一章

    第一章為什麼從「顏色和文字」開始

    每一張畫面，拆到最小都是「文字」和「顏色」。每畫一張就重新挑一次，做到後來一定對不起來：

    • 這張的按鈕是深綠，那張變成淺綠，使用者會懷疑「這兩個按鈕功能一樣嗎？」
    • 這張標題 24 號字、那張 22 號字，畫面看起來就是不整齊。
    • 老闆說「主色換成藍色」，你得一張一張找出所有綠色來改，漏一個就穿幫。
    成員可能站在客戶現場，拿起手機只想很快看一眼。字太淡看不清、該按的按鈕不夠醒目，他就會改回群組問人。顏色和文字，是「做得快、做得安心」最先碰到的一關。

    講什麼：沒有規則時會出現的三種不一致，並連回故事裡成員的使用情境。

    對應講義：第一章一節的前半。

    第一章

    什麼是顏色變數

    顏色變數就是一張有名字的色票。名字寫的是「用途」，不是顏色本身。

    • 「Primary（主要動作）」這個名字，背後存的是深綠色
    • 「Text（主要文字）」背後存的是深藍灰色
    裝潢時你跟師傅說：「客廳的牆用 A 號色。」哪天想換顏色，只要把色卡上的 A 號色換掉，所有塗 A 號色的牆就一起換。顏色變數就是 Figma 裡的這張色卡。

    講什麼：顏色變數的定義，名字寫用途；用裝潢色卡的比喻說明改一次全部一起變。

    對應講義：什麼是顏色變數，定義段與裝潢比喻。

    第一章

    用顏色變數的三個好處

    好處沒有變數時會怎樣有變數時
    一致每次憑感覺挑，深綠、淺綠混著用同一個用途，一定是同一個顏色
    好改主色要換，得一張一張找改一次色票，所有用到的地方一起變
    好溝通跟工程師說「那個深綠色」，對方不知道是哪個大家都說「Primary」，不會搞錯
    • #245B45 這樣的字是色碼，電腦用來表示顏色的編號。不用背，只要記得名字。
    • 文字樣式也是同一個概念：把字型、字多大、多粗、行距多少存成有名字的設定，例如「Type/Page title 畫面標題」。

    講什麼：一致、好改、好溝通三個好處；順帶介紹色碼與文字樣式這兩個之後常出現的詞。

    對應講義：用顏色變數的三個好處，以及其後關於色碼和文字樣式的兩段。
